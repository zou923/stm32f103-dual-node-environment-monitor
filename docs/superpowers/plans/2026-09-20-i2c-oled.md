# I2C OLED Self-Test Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Display `Hello STM32` on the 3.3 V SSD1306 OLED over I2C1/PB6/PB7 while retaining PC13 blinking.

**Architecture:** Add a focused SSD1306 module that owns I2C1 setup, bounded I2C transfers, display initialization, framebuffer flushing, and minimal glyph rendering. The application calls the module once at boot, then continues its LED loop.

**Tech Stack:** C, STM32F1 Standard Peripheral Library, hardware I2C1, CMake/Ninja, OpenOCD through CMSIS-DAP.

**Spec:** `docs/superpowers/specs/2026-09-20-i2c-oled-design.md`

## Global Constraints

- PB6 is I2C1 SCL and PB7 is I2C1 SDA.
- OLED supply is 3.3 V with common ground.
- Target is SSD1306-compatible 128x64 and uses 7-bit I2C address `0x3C`.
- Keep DAPLink/CMSIS-DAP build and flash workflow.

## Review Focus

- A missing OLED ACK must not prevent PC13 from blinking; Task 1 tests bounded transfer polling.
- The `0x3C` 7-bit address must be converted to the F1 8-bit write address; Task 1 tests it.
- I2C1 must use PB6/PB7 in alternate-function open-drain mode; Task 1 tests the source configuration.
- The complete 128x64 framebuffer must be flushed across all eight pages; Task 2 tests page loop bounds.
- The startup application must call the OLED self-test before the LED loop; Task 3 tests the integration call.
